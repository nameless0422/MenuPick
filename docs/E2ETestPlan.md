# 브라우저 E2E 테스트

## 목적

Playwright Chromium으로 사용자가 처음 가입한 뒤 실제 방문 기록을 남길 때까지의 핵심 화면
연결이 끊기지 않는지 검증한다.

검증 경로는 다음과 같다.

1. 이메일 가입과 인증 링크 처리
2. 메뉴 등록
3. 카카오 장소 검색 결과로 식당 저장
4. 저장한 식당과 메뉴 연결
5. 오늘의 메뉴 픽
6. 히스토리에서 방문 처리

테스트는 버튼 이름과 입력 레이블을 통해 조작한다. 따라서 라우팅과 React Query 캐시뿐 아니라
사용자가 실제로 접근하는 폼·버튼의 이름도 함께 회귀 검증한다.

## 테스트 경계

`frontend/e2e/core-journey.spec.ts`가 브라우저의 `/api/v1/**` 요청을 가로채 상태 기반 가짜 API로
응답한다. 메뉴를 만들고 식당을 저장한 뒤 둘을 연결하지 않으면 픽 요청이 실패하도록 구성해,
각 화면을 독립된 정적 응답으로만 확인하지 않는다.

이 테스트가 보장하는 범위는 **프론트엔드 핵심 사용자 여정**이다. 실제 Spring API, MySQL 스키마와
트랜잭션은 백엔드의 단위·통합·Testcontainers 테스트가 담당한다. 카카오 API와 메일 발송도 이
테스트 범위에서 제외해 외부 서비스 상태 때문에 CI가 흔들리지 않게 한다. 전체 운영 연동 확인은
배포 후 스모크 테스트로 별도 수행한다.

## 실행

처음 한 번 Chromium을 설치한다.

```bash
cd frontend
npx playwright install chromium
```

이후 테스트를 실행한다.

```bash
npm run test:e2e
```

GitHub Actions의 `frontend` 잡은 Chromium과 Linux 의존성을 설치한 뒤 이 테스트를 실행하며,
실패하면 `playwright-report` 아티팩트를 남긴다.
