## 제품 완성도

### 2026-11-07 추가 보안 분석과 인프라 이미지 하드닝 (운영 미배포)

- 전수 재점검 + 웹 리서치로 새 취약점을 찾아 둘로 나눠 올렸다(둘 다 머지 전).
  - **인증 메일 탈취(CVE-2019-19844 류)**: `email`·`social_id`가 accent-insensitive 콜레이션이라
    `victim@exámple.com` 변형이 조회에서 victim 행과 매칭되는데 토큰을 입력 주소로 보냈다. 등록된
    `social_id`로만 보내고 NFKC·바이트 동일성 가드를 더해 막았다(D-071).
  - **런타임 이미지 위생**: redis를 EOSL(Alpine 3.21)에서 `8.2-alpine`으로, mysql을 EOL(8.0)에서
    `8.4` LTS로 올리고 digest로 고정, 주간 `infra-image-scan`을 추가했다(D-072). 소스 tarball을
    리포에서 제거했다.
- 안전 확인: 비밀 유출 없음(gitleaks 2건은 테스트 픽스처 JWT, 운영은 전부 env). Spring 2026

## 서버 보안

### 메일 발송 — 개발 서버는 Mailpit

`MAIL_HOST=mailpit`, `MAIL_PORT=1025`. 실제 공급자를 가리키던 것을 2026-09-09에 바꿨다.
테스트 계정을 만들 때마다 진짜 메일이 밖으로 나가고, 존재하지 않는 주소로는 인증 링크를
받을 방법이 아예 없기 때문이다(토큰은 Redis에 해시로만 저장돼 서버에서 원문을 꺼낼 수 없다).
받은 메일은 `http://localhost:8025`(SSH 터널)에서 본다.

**정식 서비스 전환 시 실제 SMTP 공급자로 되돌릴 것.** 그대로 두면 가입자가 인증 메일을
영영 못 받는데 앱은 정상 기동하므로 아무도 알아채지 못한다. 근거와 절차는
[.env.prod.example](../.env.prod.example)의 MAIL 절에 함께 적어 뒀다.

### 2026-09-12 픽 쿼리 예산 고정

- 픽 한 번이 던지는 JDBC 구문 수를 테스트로 못 박았다 — 필터 없음 **7건**, 필터 있음 **12건**.
- 후보를 3배로 늘려도 조회가 비례해 늘지 않는 것(N+1 부재)도 함께 고정했다.
- 왜 필요했나: 추천 중복 완화·피드백 보정·기본 제외 태그가 각각 조회를 하나씩 얹었는데
  **기능별 테스트는 전부 초록불이었고**, 조회가 늘어난 사실은 2026-09-10 부하 시험에서야
  드러났다. 이제 같은 일이 생기면 CI에서 걸린다.
- 필터 픽 12건 중 `history_filter_conditions` INSERT 3건이 한 번으로 묶이지 않는데, 배치
  설정 문제가 아니라 **IDENTITY 키 생성** 때문이다(생성된 키를 받으려 즉시 실행해야 해
  JDBC 배치가 성립하지 않는다). 줄이려면 키 전략을 바꿔야 하고 그건 마이그레이션이라
  여기서 다루지 않았다.

### 2026-09-13 상황별 빠른 픽 (프리셋)

자주 쓰는 픽 조건에 이름을 붙여 저장하고 다시 실행한다(사용자당 10개). 설계는
[PickPresetDesign.md](PickPresetDesign.md), 결정 근거는 [D-039](DecisionLog.md)·[D-040](DecisionLog.md).

- 저장하는 것은 카테고리·포함 태그·**추가** 제외 태그·거리뿐이다.
- **좌표를 저장하지 않는다.** 거리 기준점은 실행할 때마다 브라우저에서 새로 받는다 —
  회사에서 만든 프리셋을 집에서 눌렀을 때 회사 주변을 뽑지 않기 위해서다.
- **기본 제외 태그를 복사하지 않고** 실행할 때마다 최신 값을 합친다. 프리셋이 기본 제외를
  **해제할 수단은 없다**. 유효 제외가 50개를 넘으면 자르지 않고 409로 멈춘다.
- **참조 태그가 지워지면 실행이 막힌다**(`needsReview`, 버전도 함께 오른다). 사용자가 전체
  조건을 다시 확인해 저장해야 풀린다 — 조건이 조용히 넓어진 채로 추천이 나가지 않게.
- 실행은 전용 경로 `POST /pick/presets/{id}/pick`이고 필터 override를 받지 않는다.
  일반 `POST /pick`의 계약(명시 제외 20 상한, null/빈 배열 의미)과 **쿼리 예산 7/12는 그대로다.**
  빠른 픽 실행은 별도 예산 14로 따로 고정했다.
- `main` 커밋 `c4e0bd7`로 **운영 배포를 완료했다**(2026-09-13).
