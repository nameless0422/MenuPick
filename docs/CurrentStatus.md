# MenuPick 현재 상태

**최종 갱신: 2026-09-09 / 기준 브랜치: `main`**

이 문서는 구현·배포·운영의 현재 상태를 빠르게 확인하는 요약이다. 세부 기능 계약은
[Specification.md](Specification.md), 설계 근거는 [DecisionLog.md](DecisionLog.md), 운영 절차는
[deploy/oci/README.md](../deploy/oci/README.md)를 따른다.

## 제품 완성도

- 이메일·카카오·구글 로그인, 메일 인증, 비밀번호 재설정, 계정 연동·탈퇴·복구 구현 완료
- 메뉴·카테고리·태그·식당 관리와 메뉴-식당 연결, 별점·메모 구현 완료
- 카테고리·포함/제외 태그·거리 조건을 적용한 가중 랜덤 픽 구현 완료
- 픽 히스토리, 방문 처리, 필터 조건 기록 구현 완료
- 로그인부터 설정까지 주요 React 화면과 접근성 보완 구현 완료
- 게스트 데모 픽 구현 완료
- 가입→메뉴 등록→식당 저장·연결→픽→방문 처리 핵심 여정을 Playwright Chromium으로 검증

### 2026-09-06 추천 품질 개선

- 최근 3일에 추천된 메뉴는 대체 후보가 있을 때 우선 제외한다.
- 모든 후보가 최근 추천 메뉴라면 원래 후보로 폴백해 추천 자체가 막히지 않는다.
- 픽 결과에 선호도, 카테고리·태그·거리 조건, 최근 미추천 여부를 추천 이유로 표시한다.
- 구버전 API 응답에는 추천 이유를 빈 목록으로 처리해 배포 전환 중에도 화면이 깨지지 않는다.
- 픽 직후 `이걸로 먹을래요`·`별로예요` 피드백을 히스토리에 별도 기록한다. 실제 방문 기록과
  섞지 않아 추천 직후의 선택 의도를 보존한다.

### 2026-09-07 피드백 기반 개인화

- 최근 30일간 메뉴별 긍정·부정 피드백의 차이를 추천 시 유효 가중치에 반영한다.
- 한 메뉴의 보정 폭은 ±2, 최종 유효 가중치는 최소 1로 제한해 소량의 피드백이 추천을
  과도하게 지배하거나 메뉴를 완전히 배제하지 않게 했다.
- 사용자가 직접 설정한 기본 선호도(`menus.weight`)는 변경하지 않는다.
- 보정이 적용된 결과에는 `최근 30일간 선택 피드백을 반영했어요`라는 추천 이유를 표시한다.

### 2026-09-08 기본 제외 태그

- 설정에서 알레르기·기피 태그를 기본 제외 조건으로 저장할 수 있다.
- 픽 요청이 제외 태그를 생략하면 서버가 기본값을 적용하므로 다른 클라이언트에서도 안전하다.
- 픽 화면은 기본값을 먼저 보여주며, 빈 배열을 명시해 해당 픽에서만 전부 해제할 수 있다.

### 2026-09-08 핵심 사용자 여정 E2E

- 실제 Chromium에서 가입부터 방문 처리까지 여섯 화면의 연결을 자동 검증한다.
- 상태 기반 API 대역을 사용해 앞 단계가 완료되지 않으면 픽이 성공하지 않도록 했다.
- 실제 백엔드·MySQL 계약은 기존 통합 테스트가 담당하고, 외부 카카오·메일 장애는 브라우저
  테스트에서 분리한다. 범위와 실행법은 [E2ETestPlan.md](E2ETestPlan.md)에 정리했다.

## 성능·배포

- 2026-09-04 실제 부하 시험에서 일반 100 rps 구간을 통과했고 무릎은 약 450~500 rps에서
  확인했다. 상세 수치는 [LoadTestResults.md](LoadTestResults.md)에 기록돼 있다.
- nginx `worker_connections`는 1,024에서 4,096으로 올렸고 컨테이너 `nofile`은 65,535다.
- 프론트·백엔드 이미지는 CI가 `linux/amd64`, `linux/arm64`로 GHCR에 게시한다.
- Hikari 최대 풀 크기는 `DB_MAX_POOL_SIZE`로 외부화했다. 기본값 10은 유지하며 10→16 A/B
  시험의 채택·롤백 기준을 [LoadTestResults.md](LoadTestResults.md)에 정의했다.

## 서버 보안

2026-09-05 접근 로그 점검에서 공개 SSH를 향한 무작위 계정 스캔 978건과 `/.env` 웹 스캔을
확인했지만, 알 수 없는 IP의 로그인 성공·환경파일 노출·애플리케이션 침입 흔적은 없었다.

- SSH는 `opc` 공개키 로그인만 허용한다.
- 비밀번호·키보드 대화식 인증과 root 로그인을 차단했고 `MaxAuthTries`는 3이다.
- fail2ban이 10분 내 3회 실패한 IP를 1시간 차단하며 반복 시 최대 1일까지 늘린다.
- nginx는 `/.env`, `/.git` 등 숨김파일 경로를 404로 반환한다.
- MySQL·Redis·애플리케이션·Mailpit 관리 포트는 인터넷에 직접 공개하지 않는다.
- 커밋 `120095d`, PR #220(dev)·#221(main), main CI run `33968672848` 통과.

### 메일 발송 — 개발 서버는 Mailpit

`MAIL_HOST=mailpit`, `MAIL_PORT=1025`. 실제 공급자를 가리키던 것을 2026-09-09에 바꿨다.
테스트 계정을 만들 때마다 진짜 메일이 밖으로 나가고, 존재하지 않는 주소로는 인증 링크를
받을 방법이 아예 없기 때문이다(토큰은 Redis에 해시로만 저장돼 서버에서 원문을 꺼낼 수 없다).
받은 메일은 `http://localhost:8025`(SSH 터널)에서 본다.

**정식 서비스 전환 시 실제 SMTP 공급자로 되돌릴 것.** 그대로 두면 가입자가 인증 메일을
영영 못 받는데 앱은 정상 기동하므로 아무도 알아채지 못한다. 근거와 절차는
[.env.prod.example](../.env.prod.example)의 MAIL 절에 함께 적어 뒀다.

### 2026-09-09 KPI 집계

- 방문율·재픽률·7일 리텐션을 `GET /actuator/kpi`가 실제로 계산한다(관리 포트 전용).
- 세 지표 모두 비율과 함께 분자·분모를 준다. 분모가 0이면 비율은 `null`이다 —
  "표본 없음"을 `0.0`으로 채우면 "성과 나쁨"으로 읽힌다.
- 7일 리텐션은 첫 픽 후 7일이 지나지 않은 사용자를 분모에서 뺀다. 넣으면 신규 가입이
  늘수록 리텐션이 떨어지는 착시가 생긴다.
- 기본 집계 기간 30일은 개인화 보정이 보는 창과 맞춘 값이다.
