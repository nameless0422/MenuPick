## 1. 핵심 유저 스토리 및 수용 기준

### US-1. 소셜 로그인으로 시작한다
**로서** 신규 사용자, **하고 싶다** 카카오/구글 계정으로 바로 가입·로그인, **그래서** 별도 회원가입 절차 없이 서비스를 쓴다.

- [ ] 카카오 또는 구글 인가 코드로 로그인하면 신규 유저는 자동 생성된다.
- [ ] 이미 가입된 이메일로 다른 소셜 로그인을 하면 기존 계정에 자동 통합된다([Planning.md 4.1](Planning.md#41-소셜-로그인-플로우)).
- [ ] Access Token은 응답 바디로, Refresh Token은 HttpOnly 쿠키로 전달된다.

### US-2. 내 메뉴 목록을 관리한다
**로서** 사용자, **하고 싶다** 자주 먹는 메뉴를 등록·태그·가중치로 관리, **그래서** 추천이 내 취향에 맞게 나온다.

- [ ] 메뉴에 이름/카테고리/태그/가중치(선호도)를 설정할 수 있다.
- [ ] 특정 메뉴를 추천 후보에서 제외(exclude)할 수 있고, 다시 포함시킬 수 있다.
- [ ] 태그는 자동완성 검색이 된다.

### US-3. 내 식당을 등록하고 메뉴와 연결한다
**로서** 사용자, **하고 싶다** 자주 가는 식당을 저장하고 메뉴와 연결, **그래서** "이 메뉴는 어디서 먹지"까지 추천받는다.

- [ ] 식당은 이름/주소/좌표(네이버 지오코딩)로 등록된다.
- [ ] 메뉴 1개에 여러 식당을 연결할 수 있고(`menu_restaurants`), 별점을 남길 수 있다.
- [ ] 삭제된 식당은 추천 후보 계산에서 제외된다.

### US-4. 랜덤 픽으로 오늘 뭐 먹을지 정한다
**로서** 사용자, **하고 싶다** 카테고리/태그 필터와 현재 위치를 기준으로 메뉴를 랜덤 추천받기, **그래서** 결정 피로 없이 빠르게 정한다.

- [ ] 카테고리·포함태그·제외태그·최대거리로 후보를 필터링한 뒤 가중 랜덤으로 1개를 뽑는다.
- [ ] 위치를 제공하면 연결된 식당 중 최근접 식당이 함께 기록된다. 위치가 없으면 연결 식당이 하나뿐일 때만 기록한다([Planning.md](Planning.md) — 잘못된 식당을 기록하지 않기 위한 의도적 제약).
- [ ] 후보가 없으면 `NO_PICK_CANDIDATES` 에러로 명확히 안내한다.

### US-5. 픽 이력을 돌아보고 방문 여부를 기록한다
**로서** 사용자, **하고 싶다** 지난 픽 목록을 보고 실제로 방문했는지 표시, **그래서** "그때 어디 갔었지"를 나중에 참고한다.

- [ ] 픽할 때마다 히스토리가 자동 저장된다(추천 시각, 메뉴, 식당, 적용된 필터 조건).
- [ ] 방문 처리(`PATCH /history/{id}/visit`) 시 실제 방문한 식당으로 덮어쓸 수 있다.
- [ ] 히스토리는 최신순으로 커서 페이지네이션 조회된다.

### US-6. 탈퇴해도 30일 안에는 되돌릴 수 있다
**로서** 사용자, **하고 싶다** 탈퇴 후에도 잠깐 마음이 바뀌면 계정을 복구, **그래서** 실수로 탈퇴해도 데이터를 잃지 않는다.

- [ ] 탈퇴 시 Soft delete + Refresh Token 즉시 삭제.
- [ ] 30일 내 재로그인하면 계정이 자동 복구되고 최신 OAuth 프로필로 갱신된다.
- [ ] 30일 경과 후에는 배치가 데이터를 하드 삭제하며 복구 불가능하다([PrivacyReview.md](PrivacyReview.md)와 연동해 사용자에게 사전 고지 필요).

## 2. 추천 품질 지표 (KPI)

추천 서비스의 핵심 가치는 "이 추천이 실제로 쓸모 있었는가"다. 아래 3개 지표를 최소선으로 추적한다. 현재 스키마(`histories.is_visited`, `histories.recommended_at`)로 바로 계산 가능하다.

| 지표 | 정의 | 계산 방법 (SQL 스케치) | 목표(초기, 조정 가능) |
| --- | --- | --- | --- |
| **픽 후 방문율** | 추천받은 메뉴를 실제로 방문 처리한 비율 | `count(is_visited=true) / count(*)` (기간 필터) | 30% 이상 |
| **재픽률** | 하루 안에 같은 사용자가 픽을 다시 요청하는 비율 (첫 추천이 마음에 안 들었다는 신호) | 사용자별 `recommended_at`을 시간순 정렬 후 같은 날 2회 이상 픽한 사용자 비율 | 20% 이하 (낮을수록 좋음) |
| **7일 리텐션** | 첫 픽 후 7일 이내 다시 픽한 사용자 비율 | 사용자별 최초 `recommended_at`과 이후 `recommended_at` 비교 | 25% 이상 |

> 목표값은 실사용 데이터가 없는 상태의 잠정치다. 실제 서비스 공개 후 첫 1~2개월 데이터로 재보정한다. 지표 집계 배치/대시보드는 별도 과제(운영 전환 이후).
